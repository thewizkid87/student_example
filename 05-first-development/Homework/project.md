# Week 5 Home Project: Complete The MVP

## What

Complete development of your MVP.

Start from the app skeleton and first MVP feature you created in class. Continue working through `<idea>-tasks-final.md` until every MVP task is implemented, the app runs locally, and the project is ready for feedback in the next lesson.

This homework is not limited to 240 minutes. Continue until the MVP is complete.

## Why

The next lesson starts from a working MVP. You will use that running app to gather feedback, decide what should improve, and plan the next version.

This is how development work often feels in practice: the task is done when the required software state is reached, not when a timer ends.

## How

Work from:

- `project-hld.md`
- `<idea>-tasks-final.md`
- the app files created during class

Use [implementation-loop-prompt.md](../Files/implementation-loop-prompt.md) to keep each Codex request focused on one task. Use [debugging-prompt.md](../Files/debugging-prompt.md) when you hit an error, and paste the exact command output, browser console message, or stack trace.

If Codex says a tool or runtime is missing, ask it to recommend the best install method for your system before installing anything. Node.js is the recommended default for simple browser apps, but your project should follow the stack selected in your planning files.

Do not ask Codex to build the whole app in one prompt. Complete one task, run the app, inspect the result, debug if needed, commit, then move to the next task.

## Acceptance Criteria

- The project runs locally.
- The app skeleton exists.
- At least one visible MVP feature was completed during class.
- All MVP features from `<idea>-tasks-final.md` are implemented.
- Implementation follows `project-hld.md`.
- Implementation work comes from `<idea>-tasks-final.md`.
- Browser storage is implemented if the MVP needs saved data.
- No real backend or database was added unless it was explicitly approved in `project-hld.md`.
- Codex was used task by task, not with one broad "build the whole app" prompt.
- Debugging fixes are reflected in code changes or commits.
- Multiple meaningful commits exist.
- The MVP is ready for feedback in the next lesson.
- The latest work is pushed to GitHub.

## Work Blocks

This homework is not time-capped. Continue until the full MVP is complete.

| Work Block | Activity | Done When |
| --- | --- | --- |
| 1 | Review `project-hld.md`, `<idea>-tasks-final.md`, and class progress. | You know which MVP tasks are complete, partial, or not started. |
| 2 | Verify the app runs locally. | You can start the app with the local run command and see it open without setup errors. |
| 3 | Implement the remaining MVP tasks one task at a time. | Every MVP task from `<idea>-tasks-final.md` has working code. |
| 4 | Run the app after each meaningful change. | You have checked the feature in the browser or terminal before moving on. |
| 5 | Debug broken behavior with Codex. | You used exact errors, command output, browser console messages, or stack traces to fix failures. |
| 6 | Commit each completed MVP task or meaningful fix. | Your Git history shows multiple clear implementation commits. |
| 7 | Ask Codex to review the implementation. | Codex compared the app to `project-hld.md` and `<idea>-tasks-final.md`, and you acted on important findings. |
| 8 | Push to GitHub and verify the repository. | GitHub shows the latest commits and the completed MVP files. |

## Submission

Commit and push:

- all source files needed to run the MVP
- any package or dependency files created by the selected stack
- any notes or comments needed to preserve the local run command

Your pushed repository should show a running MVP that is ready for feedback in the next lesson.
