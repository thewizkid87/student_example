# User And Problem Cheatsheet

Use this cheatsheet when Codex gives you a plan that sounds polished but feels vague.

## Core Terms

| Term | Meaning | Weak Example | Stronger Example |
| --- | --- | --- | --- |
| Target user | The type of person who needs the project. | Everyone | A learner who needs quick calculations while doing homework. |
| User persona | A practical snapshot of the user and their situation. | A person who likes apps | Taylor, a learner using a laptop for homework, wants quick calculations without distractions. |
| Problem | The difficulty the user has. | Needs a calculator | Needs quick basic arithmetic without ads, accounts, or extra modes. |
| Solution | The software response to the problem. | Make an app | Build a local browser calculator with clear buttons and basic arithmetic. |
| Risk | Something that could make the plan fail or become unclear. | Bugs | Invalid input and division by zero may break the calculator flow. |

## Better Planning Questions

- Who has this problem?
- When does the problem happen?
- What does the user do today without this tool?
- What is annoying, slow, confusing, or missing from the current solution?
- What would make the first version useful enough?
- What could make the first version harder than expected?

## Prompt Examples

Ask Codex:

```text
Read my summary file.
Is the target user specific enough?
If not, ask me three questions that would make the user clearer.
```

Ask Codex:

```text
Read my summary file.
Does the problem describe a real user need, or is it just a feature idea?
Explain what is missing and suggest a stronger problem statement.
```

Ask Codex:

```text
Create a practical user persona for this idea.
Do not make it a long biography.
Include the user's goal, situation, and constraint.
```
