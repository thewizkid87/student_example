# Week 3 Enrichment: Planning With AI

These topics are optional. Use them if you want more context on why planning quality affects the software you eventually build.

## Optional Topics

### Product Management

Product management is the practice of deciding what should be built, why it should be built, and how it creates value for users. For Week 3, focus on the product question behind the planning files: does this idea solve a meaningful problem for a specific user?

- Read: [What is product management?](https://www.productplan.com/learn/what-is-product-management)
- Read: [IBM product management overview](https://www.ibm.com/think/topics/product-management)

### User Stories

User stories describe work from the user's point of view. They can help you turn a feature into a statement about who needs it, what they need, and why it matters.

- Read: [Atlassian user stories guide](https://www.atlassian.com/agile/project-management/user-stories)

### Jobs To Be Done

Jobs To Be Done focuses on the progress a person is trying to make. It can improve your summary file because it pushes you to ask what the user is trying to accomplish, not only what feature they requested.

- Read: [Jobs To Be Done Theory](https://www.christenseninstitute.org/theory/jobs-to-be-done/)
- Watch: [What is Jobs To Be Done Theory?](https://www.christenseninstitute.org/video/what-is-jobs-to-be-done-theory/)

### Requirements Quality

Requirements describe what the software must do, who it is for, and what conditions must be true for the work to be considered complete. Better requirements make the MVP and tasks files easier to generate and easier to build from.

- Read: [What is a Product Requirements Document (PRD)?](https://www.atlassian.com/agile/product-management/requirements)

### Scope Control

Scope control is the practice of deciding what belongs in the current version and what should wait. It helps prevent the first build from becoming too large to finish.

- Read: [Minimum viable product guide](https://www.productplan.com/glossary/minimum-viable-product/)

## Stretch Activity

Choose one of your Week 3 idea summaries and improve it using Jobs To Be Done.

Add a short section to the summary file:

```md
## Job To Be Done

When [situation], I want to [motivation], so I can [expected outcome].
```

Then ask Codex:

```text
Read this summary and the Job To Be Done section.
What MVP features now look stronger?
What features now look less important?
What risks should I add?
```

## Exploration Question

Why do many software projects fail before a single line of code is written?

Use your Week 3 files to answer the question. Look for places where the user is vague, the problem is unclear, the MVP is too large, or the tasks are not specific enough to execute.
