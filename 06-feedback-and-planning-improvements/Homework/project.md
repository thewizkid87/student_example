# Week 6 Home Project: Feedback Plan And Improvement Tasks

## What

Create a feedback-based improvement plan for your MVP.

Start from the feedback you gathered in class, then try to get one more round of feedback from a friend or family member. Use all feedback received, the running MVP, `project-hld.md`, and `<idea>-tasks-final.md` to finish `feedback-plan.md`, then create `<idea>-improvement-tasks.md` for Week 7.

## Why

A working MVP is not the end of development. Feedback helps you find bugs, confusion, missing value, and useful improvements.

The goal is to turn feedback into decisions. You should not build every request. You should choose the next small set of improvements that make the MVP stronger without restarting the project.

## How

Work from:

- the running MVP
- class feedback notes
- friend or family feedback notes, if you can get them
- `project-hld.md`
- `<idea>-tasks-final.md`
- [feedback-capture-cheatsheet.md](../Files/feedback-capture-cheatsheet.md)
- [prioritization-cheatsheet.md](../Files/prioritization-cheatsheet.md)

Before you start the plan, show the MVP to a friend or family member if possible. Ask them to try the core flow, watch where they pause, and write down what they say in their own words.

If you cannot get outside feedback, continue with class feedback and write that no outside feedback was available.

Use [feedback-categorization-prompt.md](../Files/feedback-categorization-prompt.md) to group the raw feedback. Use [prioritization-prompt.md](../Files/prioritization-prompt.md) to decide what to accept, reject, defer, or investigate.

Use [feedback-plan-prompt.md](../Files/feedback-plan-prompt.md) to create or revise `feedback-plan.md`. Use [improvement-tasks-prompt.md](../Files/improvement-tasks-prompt.md) to create `<idea>-improvement-tasks.md`.

Ask Codex to critique both files before you finish. Revise the plan when Codex finds unclear decisions, oversized tasks, missing verification steps, or scope that is too large for Week 7 development.

## Acceptance Criteria

- `feedback-plan.md` exists.
- `feedback-plan.md` includes class feedback and friend or family feedback if available.
- `feedback-plan.md` notes if outside feedback was not available.
- `feedback-plan.md` includes feedback received, categories, bugs found, feature requests, decisions made, selected improvements, deferred ideas, risks or open questions, and a Week 7 roadmap.
- `<idea>-improvement-tasks.md` exists.
- Each improvement task is small enough for Week 7 development.
- Each improvement task includes what should change, why it matters, how to verify it, and what done looks like.
- The plan distinguishes bugs from feature requests.
- The plan distinguishes accepted work from deferred, rejected, or investigate work.
- Codex was used to categorize feedback and critique the plan.
- The final plan reflects at least one revision after critique.
- The required files are committed and pushed to GitHub.
