# Week 1 Enrichment

## Optional Topics

### GitFlow

GitFlow is a branch-based workflow with a long-lived `develop` branch for integration and a `main` or `master` branch for release history. Feature branches merge into `develop`, then release branches merge into both `develop` and `main` when a version is ready.

- Read: [A successful Git branching model](https://nvie.com/posts/a-successful-git-branching-model/)
- Read: [Gitflow workflow](https://www.atlassian.com/git/tutorials/comparing-workflows/gitflow-workflow)
- Watch: [A git-flow screencast](https://nvie.com/posts/a-git-flow-screencast/)

### Branching Strategies

Branching strategies help a team decide how to keep work separated while people build features in parallel.

- Read: [About branches](https://docs.github.com/articles/about-branches)
- Watch: [Git Fundamentals](https://learn.microsoft.com/en-us/shows/visual-studio-toolbox/git-fundamentals)

### Pull Requests

Pull requests let you propose changes, ask for review, and merge work back into the main branch.

- Read: [Pull requests documentation](https://docs.github.com/en/pull-requests)
- Watch: [Introducing GitHub pull requests for Visual Studio Code](https://learn.microsoft.com/en-us/shows/azure-devops-launch-2018/a107)

### GitHub Discussions

GitHub Discussions is a place for questions, ideas, and conversation that do not need to be tracked as code changes.

- Read: [GitHub Discussions](https://docs.github.com/en/discussions)

### GitHub Projects

GitHub Projects gives you a visual board or table to plan work and track progress.

- Read: [About Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects)

## Optional Tools

### GitHub Desktop

GitHub Desktop is a visual app for cloning, committing, branching, and pushing without staying in the terminal all the time.

- Read: [About GitHub Desktop](https://docs.github.com/en/desktop/overview/about-github-desktop)

### Fork

A fork is a personal copy of another repository that you can edit without changing the original project directly.

- Read: [About forks](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/working-with-forks/about-forks)

### Visual Studio Code

Visual Studio Code is the editor you will use to write, review, and organize course files.

- Read: [Get started with Visual Studio Code](https://code.visualstudio.com/docs/getstarted/overview)
- Watch: [Visual Studio Code](https://learn.microsoft.com/en-gb/shows/visual-studio-code/)

### Windows Subsystem for Linux

WSL lets Windows users work in a Linux-style terminal environment for Git and Bash commands.

- Read: [Install WSL](https://learn.microsoft.com/en-us/windows/wsl/install)
- Watch: [Why should I use WSL?](https://learn.microsoft.com/en-us/shows/one-dev-minute/im-a-windows-developer-why-should-i-use-wsl--one-dev-minute)

## Optional Skills

### Basic Bash Commands

Basic Bash commands help you move around folders, create files, and inspect what is in your workspace.

- Read: [GNU Bash manual](https://www.gnu.org/software/bash/manual/)

### Terminal Navigation

Terminal navigation is the skill of moving through folders and understanding where your files live.

- Read: [Introduction to Bash](https://www.gnu.org/software/bash/manual/html_node/Introduction.html)

### File Permissions

File permissions control who can read, write, or run a file, which matters when you make scripts executable.

- Read: [File permissions](https://www.gnu.org/software/coreutils/manual/html_node/File-permissions.html)

### SSH Keys

SSH keys are one way to authenticate with GitHub without typing your password for every Git operation.

- Read: [Connecting to GitHub with SSH](https://docs.github.com/en/authentication/connecting-to-github-with-ssh)
