# Week 4 Home Project: Finalize Project Scope And Tasks

## What

Finish the project planning work you started in class.

In the next lesson, you will start implementation from these files. We will not spend class time going over every HLD, task list, and planning detail from the beginning, so your plan needs to be ready before Week 5 starts.

The last file you should create or revise is `<idea>-tasks-final.md`. It must be based on `project-hld.md` because the final task list is what you will use to start development next lesson.

By the end of the homework, your repository must contain:

- `project-hld.md`
- `<idea>-tasks-final.md`

Use the same `<idea>` prefix from your selected Week 3 files. If you selected `idea-2-summary.md`, your final task file should be `idea-2-tasks-final.md`.

## Why

Week 5 begins the implementation phase. Before you start building, you need a project scope that is small enough to finish and a task list that is clear enough to develop from.

This homework exists to finish, clean up, and commit the work from class. If you completed the HLD and final task list during class, use the homework time to review, reduce scope, improve clarity, and verify that the files are ready for implementation.

## How

Start from whatever you already completed in class.

If `project-hld.md` already exists, open it first and improve it. Do not create or revise `<idea>-tasks-final.md` until the HLD is clear enough to guide development.

Use your selected Week 3 files as source material:

- `<idea>-summary.md`
- `<idea>-mvp.md`
- `<idea>-tasks.md`

Use [idea-validation-prompt.md](../Files/idea-validation-prompt.md) if you did not finish validation in class, or if your plan still feels too large or unclear.

The project should ideally:

- have about 3-4 screens or states
- store data in the browser
- avoid a real server-side backend
- avoid a real database
- be small enough to implement in one week

Use [project-hld-prompt.md](../Files/project-hld-prompt.md) to revise `project-hld.md` if it is missing, vague, or reads like a task list instead of a development blueprint.

Use [tasks-final-prompt.md](../Files/tasks-final-prompt.md) last to create or revise `<idea>-tasks-final.md` from `project-hld.md`. This is the final planning file and the starting point for Week 5 implementation.

Use [hld-cheatsheet.md](../Files/hld-cheatsheet.md), [architecture-overview-cheatsheet.md](../Files/architecture-overview-cheatsheet.md), and [task-writing-cheatsheet.md](../Files/task-writing-cheatsheet.md) while reviewing the files.

## Acceptance Criteria

- `project-hld.md` exists.
- `project-hld.md` includes a problem statement, users, features, data model, screens/pages, architecture overview, milestones, risks, and assumptions.
- The architecture overview is readable in Markdown.
- The project has about 3-4 screens or states, or `project-hld.md` explains why a different number is still small enough.
- The project can store data in the browser.
- The project does not require a real server-side backend.
- The project does not require a real database.
- The project is scoped to be built in one week.
- `<idea>-tasks-final.md` exists.
- Each task has a clear outcome.
- Each task includes acceptance criteria.
- The first implementation task creates the app skeleton for the selected language or stack.
- Codex was used to critique the HLD and final task list.
- The final files reflect at least one revision after critique.
- All required files are committed and pushed to GitHub.
