# Week 4 Enrichment

Use this only if you want to go deeper after the required project plan is finished.

## Optional Topics

### High Level Design

High level design is the bridge between idea planning and implementation. It names the main system parts, the important data, and the first build path without going deep into code details.

- Read: [System Design Primer: Create a high level design](https://github.com/donnemartin/system-design-primer#step-2-create-a-high-level-design)
- Read: [arc42 Template Overview](https://arc42.org/overview)

### System Design

System design is the process of defining components, interfaces, data, constraints, and tradeoffs. For this course, keep it small and practical unless your project actually needs deeper architecture work.

- Read: [Software Architecture Guide](https://martinfowler.com/architecture/)
- Read: [C4 model for visualising software architecture](https://c4model.com/)

### Wireframes

Wireframes are simple screen blueprints. They help you decide what the user sees before spending time on colors, styling, or detailed UI polish.

- Read: [NN/g: How to Draw a Wireframe](https://www.nngroup.com/articles/draw-wireframe-even-if-you-cant-draw/)
- Read: [NN/g: Wireflows](https://www.nngroup.com/articles/wireflows/)

### User Journey Mapping

User journey mapping shows the steps a person takes to accomplish a goal. It is useful when your project has several screens, roles, or decision points.

- Read: [NN/g: Journey Mapping 101](https://www.nngroup.com/articles/journey-mapping-101/)
- Watch: [NN/g: Journey Mapping 101 video](https://www.nngroup.com/videos/journey-mapping-101/)

### GitHub Issues

GitHub Issues are the hosted version of a project task list. They are optional in Week 4 because the required homework output is `<idea>-tasks-final.md`.

- Read: [Quickstart for GitHub Issues](https://docs.github.com/en/issues/tracking-your-work-with-issues/learning-about-issues/quickstart)
- Read: [About issues](https://docs.github.com/articles/about-issues)

### Mermaid

Mermaid is a text-based diagram format that can live inside Markdown. It is optional if you want your architecture overview to become a diagram.

- Read: [Mermaid flowchart syntax](https://mermaid.ai/open-source/syntax/flowchart.html)
- Tool: [Mermaid Live Editor](https://mermaid.live/)

## Optional Tools

### Excalidraw

Excalidraw is a simple sketching tool for diagrams, flows, and rough interface ideas. It is useful when you want a visual plan without learning a full design tool.

- Tool: [Excalidraw](https://excalidraw.com/)
- Read: [How to start drawing in Excalidraw](https://plus.excalidraw.com/how-to-start)

### Figma

Figma is a browser-based design tool for wireframes, UI mockups, and prototypes. It is more powerful than needed for many beginner projects, but useful when you want detailed screen planning.

- Tool: [Figma](https://www.figma.com/)
- Learn: [Figma Learn Help Center](https://help.figma.com/hc/en-us)

## Stretch Activity

Create two short roadmap files:

- `version-2-roadmap.md`
- `version-3-roadmap.md`

For each roadmap, list features that are useful but not needed for the first implementation.

The point is to keep good ideas without putting them into version 1.

Useful roadmap links:

- Read: [Roman Pichler: When You Should Not Use a Product Roadmap](https://www.romanpichler.com/blog/when-you-should-not-use-a-product-roadmap/)
- Read: [Roman Pichler: GO Product Roadmap](https://www.romanpichler.com/tools/the-go-product-roadmap/)
