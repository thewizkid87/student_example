# Release Notes Prompt

Use this prompt to create or revise `release-notes.md`.

Copy and paste this prompt into Codex:

```text
Read `feedback-plan.md`, `<idea>-improvement-tasks.md`, and recent commits if possible.

Create or revise `release-notes.md`.

The release notes should include:
- What changed
- What feedback was addressed
- What was fixed
- What was improved
- Known limitations
- What remains for future versions

Follow these rules:
- Keep completed work separate from future ideas.
- Do not claim a task is complete unless it is marked complete and verified.
- Mention feedback decisions when they explain why a change was made.
- Keep the language clear enough for a project reviewer or user.
- Ask me questions if the task status or completed work is unclear.

When finished, list anything that still needs verification before release.
```
